# Agent `x86`: every-count theorems of the x86 kernels

Branch `all-x86` (worktree `src/wt-x86`), remote `/root/kt-x86/lean` (rsync without `.lake`, `Gen*/`, `plans/`;
builds under `systemd-run --scope -p MemoryMax=40G`).

## Pipeline
1. `x86_all.py analyze <kernel>` → `plans/<k>_all.json`: simulates the frame's *count steps* (cmp/test/bt/jcc/
   jcct/movi/mov/sub on numbers/xorz/jmp/nop) on the `kttool paths` of every count 0..64+2N+2 and cuts each
   path into pieces: entry policy (count steps) → `P` (prologue, first non-count instruction up to the loop
   guard) → guard (count steps) → loop head `H` (`call 0`) → body → loop control `C` (`sub rdx,N; cmp; jae H`)
   → dispatch (count steps) → exit `X<j>` (from the first non-count instruction to the terminal `ret` at depth 0,
   `tailcall` or taken `jcct`; keyed by pc, the small register values and the flags).
2. `x86_all.py gen <kernel>` → generated segments (`gen_plan_proof.py`, SEG mode):
   * exits `GenX<j>` from the smallest count reaching them (count register = control constant there);
   * body split at its first flag write (the batch's round counter `dec`/`decm`): `GenBa{f,t}` proved for each
     ZF value at the loop head (ZF there is `rdx == N`, varies with the count; the flags are dead until the
     `dec`), `GenBb` the rest; mid-batch start/end invariants (matches at the cut, `aat` with an offset round);
   * prologue `GenP{zc}` per flag value it can start with (fresh call: clear flags).
   Each `Seg.lean` now also emits `facts : X86K.SegFacts rodata prog` (bundle) and `facts_rdx`.
3. `build_seg.sh <Dir> <P> <Gen...>`; `/root/kx-run.sh <kernel> <Dir> <P>` = gen + build (memory-capped).
4. `x86_glue.py <kernel>` → `Kernels/<Dir>/All.lean`: exits (`exit_X*`), `body_Ba*` (data: `inv0_*`,
   `bb_digest`), `afterB_step`/`afterB` (loop, induction on the remaining nodes), `afterP_*` (guard; literal cases
   below the uniform bound), `norm_thm : LibX86.NormThm` — then `LibX86.mkKernel` lifts it to any entry flags/masks.

## Lean infrastructure (additive)
* `Asm/X86Frame.lean`: `Fr` (count steps on concrete states for any count value: `Near`, step lemmas
  `Fr.cmpi/test/jcc/jmp/jcct_not/jcct_taken/nop/movi/mov/xorz/sub/bt`, `Fr.pc_congr`), `PreCut`, **`Fr.cut`**
  (hand-over from count steps to the next segment's relocated cut; count registers as fixed words).
* `Asm/X86Kernel.lean`: `rho m` (relocation by m nodes) + lemmas, `entrySc`/`PreCut.entry`/`Fr.entry`
  (the entry as a pseudo-cut), `SegFacts`, `seg_chain`, `run_ret0/run_tail/run_jcct`, `handover` (tail-call
  state ⇒ `LibX86.Entry` of the normalised hand-over), `Done` (outcome within a step bound; `mono`, `run`),
  `Inv` (`fr`, `seg`), `fr_cond` macro.
* Library interface: `LibX86.NormThm`/`mkKernel` (agent `lib`); hand-over = `LibX86.Entry` of `normCtl`.

## Interface notes (for agent x86b, AVX-512 family)
* `x86_all.py analyze <k>` then `gen <k>` (or `/root/kx-run.sh <k> <Dir> <P>` = gen + capped build), then
  `x86_glue.py <k>` → `All.lean` (`norm_thm`) + `Lib.lean` (`mkKernel`; AVX-512: static check fails — replace by
  `run_ovr_path`).  Loop head `H` = the batch `call 0` visited most often on the largest count.
* Masks: kernels with `kmovw` get body variants `Ba{f,t}m` (k1 = the batch's mask, env `K1` in gen_plan_proof,
  applied to the first slice's start state) for iterations ≥ 2; exits keyed also by `kset` (a batch ran before).
* Exits with own batches (padded tails): `NODES` = the exit's own nodes, `digest_<X>`/`inv0_<X>` emitted.
* `Fr.cmprm`: threshold compare against the default constant image (classes: TODO, see notes/lib.md).

## Core changes (minimal, additive in effect)
* `Asm/Iter.lean`: `E.fold` also folds a region-0 pointer (a number written by `dec`/`sub`/`call`'s return
  address) to its constant word, so a slice's end cut can keep a number as a control word (the batch round
  counter `rcx`, a return address on the stack); `E.eval_reloc_fold` now takes `hρ : ρ.ok`.
* Merged lean-verification f9fddac (all-rv, commit 2d8ec35): `E.fold` now has rv's arm `.add (.ptr a) e` with
  `e.closed = some k` → `.ptr ⟨a.region, a.off + k.toInt⟩` (signed, any closed `e`) before the x86 region-0 pointer
  arm; `eval_reloc_fold` proves both.  Existing x86 certificates stay valid: their folds were `.add (.ptr) (.const k)`
  with `k < 2^54` (else `ctlTreeOk` fails), where `toInt = toNat`; the new fold only matches more `.add` terms,
  which before stayed unfolded and so could not equal a cut's `.ptr`/`.const` control word.  kttool is rebuilt
  from the same `Iter.lean`, so generator predictions agree with the certificates.

## Pitfalls
* Spurious round-constant matches in general registers: `kttool matches` labels any 64-bit word equal to a rotated
  round constant, e.g. r10 = `1 << 56` (an output pointer) = RC0 rol 56, rdx = 8 (a count) = RC0 rol 3.  x86 applies
  the round constants from memory only, so gen_plan_proof drops RC kinds (75..98) at `.gd` locations.  Affected and
  regenerated: x9 exits X0/X1/X3, x10 exits X0/X3, x6 body.
* Scalar node (avx2_x5/x6/x9/x10: batch positions >= 4*(N//4) in the general registers, its rounds spread through
  the vector rounds): `kttool` reports it a round behind the vector lanes at a vector-round cut while its round is
  partly done; the partial outputs have no match and the lane lemmas fail ("spurious counterexample").  `window`
  now keeps a cut only where a batch containing a scalar node is at one round (avx2_x8's two vector groups keep
  their staggered cuts).  Regenerated: x5/x6/x9 bodies, x10 body and exit X4.
* Count spilled by the batch (avx2_x5/x6/x9/x10, avx512_x9/x9d: the scalar node uses rdx; `storeq [r9+SAVE_RDX], rdx`
  at the batch start, `loadq rdx, [r9+SAVE_RDX]` at the end): `moves 258:258` fails per slice.  gen_plan_proof now
  follows the count (`count_locs`: from the kttool path, only stores while rdx holds the count) and emits per-slice
  moves `(loc_out, loc_in)`, `seg_count`, and `facts_rdx` as `cell ← rdx` (Ba) / `rdx ← cell` (Bb); the glue's
  `(Bb.facts_rdx …).trans (Ba.facts_rdx …)` is unchanged.  `ONLY=B` regenerates just body and prologue (commit 88358de).
* Memory: a GenBb slice of a 5+ node kernel peaks at 10–14 GB (Avx2X10 ~14 GB), so `build_seg.sh` with P=10 hits the
  scope cap and systemd's OOMPolicy=stop SIGTERMs the whole scope ("Terminated" in the log, no ALLBUILT).  Use
  P=3 under a 50G scope (`/root/kx-queue3.sh <k>:<Dir>:<P> ...`; `kx-kall.sh` now honours its P argument).
* Plans must cut only where all nodes in progress are at the same round (`window` filter): avx2_x5/x8 advance the
  vector group a round before the other lanes; cuts in between give unprovable lane lemmas.
* Padded tails: `KT_POISON=1` (from x86b) so the dummy node hashed from stack garbage does not create bogus matches.
* `kttool matches` lanes parameter: 4 for AVX2/avx512vl kernels, 8 for avx512_x8/x9, 0 for x86_x1 (with 0 the
  partial parities are not matched and lane lemmas fail with "spurious counterexample").
* Fr.cut's decidable check must be closed: count registers with symbolic values are excluded (`fixed` list).
* Elaborating `digest_Bb … _ _ … db` with the state families as metavariables took > 10 min: pass them explicitly.
* `lake build <All>` after a core change rebuilds every slice with full parallelism (OOM risk under the cap):
  run `build_seg.sh` (bounded `P`) first.
* `kttool matches` on large counts is slow (~30 s at count 40): the exit flags are simulated in Python and checked
  once per exit with kttool.
